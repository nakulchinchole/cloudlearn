Design and Implementation of a Cloud-Based Student Resource Portal Using Amazon S3 and Amazon CloudFront CDN.

Problem statement

Students need study material they can open quickly from anywhere. A single server is slower for distant users, can fail, and is harder to secure and scale.

Objectives

  • Host a static student resource portal in Amazon S3.
  • Deliver it through Amazon CloudFront for faster, cached access.
  • Use HTTPS for secure access.
  • Keep the S3 bucket private with Origin Access Control.
  • Teach caching with interactive simulations.

Scope

A static website with six pages, ten sample PDFs and local simulators. It needs no backend, database or login. Deployment to AWS is a separate step done by the team.

Technologies

HTML5, CSS3, vanilla JavaScript, Amazon S3, Amazon CloudFront, HTTPS (TLS), Origin Access Control, localStorage for the checklist.

Architecture

Browser, then HTTPS to a CloudFront edge location, then on a cache miss a request to the private S3 bucket through Origin Access Control. See the Architecture page.

Expected results

After deployment the team expects the site to load over HTTPS from a CloudFront domain, repeated requests to be served from the edge cache, and the S3 bucket to reject direct public access. These are expectations. Measure and record your own results after deploying.

Limitations

  • Static content only, with no uploads or user accounts.
  • The console and demos are simulations, not live AWS metrics.
  • Updated files need a cache invalidation or wait for TTL.
  • Sample PDFs are short original notes, not full textbooks.

Future improvements

  • Custom domain with Route 53 and a certificate.
  • Security headers through a CloudFront response headers policy.
  • Automatic deployment with GitHub Actions.
  • Real CloudFront metrics through CloudWatch.
  • Uploads and accounts using a backend service.

Viva notes

What does S3 do?

It stores the website files as objects in a bucket. It is the origin.

What does CloudFront do?

It caches files at edge locations near users and serves them, reducing delay and origin requests.

Cache hit versus miss?

A hit is served from the edge. A miss makes CloudFront fetch from S3 first, then cache the file.

Why keep the bucket private?

So files are reachable only through CloudFront. Origin Access Control gives CloudFront permission.

Does HTTPS need a public bucket?

No. HTTPS is between the browser and CloudFront. The origin can stay private.

REST endpoint or website endpoint?

REST, because it works with OAC and a private bucket.

How do you update the site?

Upload the new files to S3, then create a CloudFront invalidation for /*.

Are the console numbers real?

No. They come from a local JavaScript simulation.
